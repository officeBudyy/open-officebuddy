# officeBuddy v0.7.1 上游同步记录

## 范围

- 参考源码：`reference/open-astravia`，桌面版本 `0.6.1`。
- officeBuddy 同步基线：上游 `0.5.83` 之后。
- 本阶段只迁移能够保持 officeBuddy 产品合同、且可以用源码与回归测试独立证明的稳定性和性能改动。

## 必须保持的不变量

1. 企业专家、团队会话进展和团队工作目录继续使用 officeBuddy 的现有实现。
2. SkillHub、技能/场景、连接器引用与输入框能力菜单的现有产品语义不变。
3. `modelOverrides` 的 300K / 600K / 1M 上下文长度覆盖继续生效。
4. officeBuddy 品牌、应用身份、数据目录、凭据兼容名和安装包名称不被上游 Astravia 常量覆盖。

## v0.7.1 第一阶段已同步

### 会话可靠性

- 会话文件追加前校验文件仍存在、inode 未替换且长度未回退。
- 并发删除/迁移不再生成没有文件头的残档。
- 损坏会话可按文件名恢复列表身份，并可通过复合目录正常删除。
- 删除会话同步清理 snapshot 与 queue sidecar。
- 快速连续切换会话时，只回收本次新建的空壳，不删除已有会话。

### 长会话性能

- Native conversation 历史支持异步读取、有限缓存和大文件 worker 解析。
- Runtime Host 增加异步文件历史读取合同；Desktop 只读 viewer 优先走异步入口。
- Runtime 与 Coding Agent 的消息编辑分支投影改为预建索引并压缩透明节点链。
- 会话列表只抽取首条用户消息与最后一条消息，不再遍历处理全部消息文本。
- 空闲 Runtime 驻留窗口从 3 个扩大到 8 个。

### 上下文压缩与记忆

- 压缩保留预算随上下文窗口缩放，并保留 15% 可增长余量。
- 结合上一次压缩结果等额收敛，避免在阈值附近反复压缩。
- 小窗口模型不再被固定 2K 保留下限卡住。
- 压缩资格按文档 revision、active leaf 与设置缓存。
- 手动压缩在两段同步投影之间让出事件循环。
- 长期记忆在历史段为空时回退到被丢弃的本轮前缀。
- 成功的手动压缩只由持久事件生成一次 `compaction.end`。

### Windows 文件树

- watcher 比较键统一斜杠、尾分隔符和 Windows 盘符大小写。
- 展开目录时增量新增/移除 watcher，组件卸载时统一释放。
- 从消息或插件定位文件时，先按工作区根目录对齐路径分隔符。

## 后续实施规则

- 每个待适配项目单独确认产品行为后再做，不把多个横切改动混成一次同步。
- 涉及冲突入口时，以 officeBuddy 当前合同为主，移植上游算法与测试，不复制整文件。
- 每批补充 `.github/release-notes/v0.7.1.md`，并运行定向测试、`check:quick` 与受影响包类型检查。
