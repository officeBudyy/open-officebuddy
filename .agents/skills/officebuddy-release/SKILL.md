# officeBuddy 发版准备

协助完成 officeBuddy 桌面应用的发布准备，基于仓库中的真实提交、版本与发布说明状态整理用户可见变更。除非用户明确授权，不执行发布、打 tag、推送或其他不可逆操作。

## 工作流程

### 1. 确认仓库与目标版本

在 officeBuddy 仓库根目录操作。先确认当前分支、工作区状态及用户是否指定了目标版本。未指定时，侦察脚本会建议 patch +1；不要将建议值视为已获批准的版本决定。

### 2. 收集本版变更

先运行本技能捆绑的只读侦察脚本，一次收集当前/目标版本、最近本地 `v*` tag、提交清单、i18n diff、未提交改动和发布说明状态：

```bash
node .agents/skills/officebuddy-release/scripts/prepare-release.mjs
node .agents/skills/officebuddy-release/scripts/prepare-release.mjs --version X.Y.Z
```

第二条仅在用户已给出版本号时使用。脚本不修改文件。提交清单最多显示 30 条；报告未找到 tag 时，提交范围只能作有限参考。

### 3. 判断用户可见变更

逐条检查提交和 locale diff，识别新增/改变的页面、功能、设置和交互。排除纯格式化、内部重构及文档维护等不面向用户的变更；不能仅凭提交标题或 i18n 文件变化推断功能。发布说明必须基于已核实的实际改动，不得编造。

留意并向用户明确指出：

- 未提交改动或未跟踪文件：默认不纳入发布范围，先确认归属。
- 未找到本地发布 tag：远端可能有更新的 tag。必要时询问后执行 `git fetch --tags`，再重跑侦察；fetch 会访问远端并更新本地 tag 信息。
- 上个版本发布说明在 tag 后被修改：报告会列出相关提交，需人工判断，不要悄悄覆盖或纳入。
- 目标版本的发布说明已存在：在用户确认后补充，不覆盖原文。
- 官网版本同步状态无法自动确认：按报告提示手工检查。

### 4. 经确认后准备版本文件

向用户汇总建议版本、纳入的变更、排除项和发布说明草案。获得用户确认后，才修改 `apps/desktop/package.json` 与 `.github/release-notes/vX.Y.Z.md`。写入后运行仓库定义的发布说明检查及 `node scripts/release/resolve-desktop-release-config.mjs` 验证，并报告结果。

不得仅凭本技能自动执行发布命令、创建/推送 tag、推送分支或上传构建产物；这些步骤需要用户另行明确授权。

## 捆绑脚本

`scripts/prepare-release.mjs` 是只读侦察工具。它通过技能所在项目定位仓库根目录，可从仓库任意子目录调用。变更脚本时保持只读性质，并至少验证默认版本、显式版本及非仓库目录调用场景。
